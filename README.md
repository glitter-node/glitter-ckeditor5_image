# Glitter CKEditor5 Image

그누보드7 플러그인. 글·댓글 본문에 들어 있는 **에디터 업로드 이미지**를 방문자에게 더
적은 바이트로 보냅니다.

- 라이선스: MIT
- 요구 사항: 그누보드7 7.0.10 이상, `sirsoft-ckeditor5` 1.0.3 이상, PHP imagick 확장

## 무엇을 하나

### 1. 중간 크기 변환본

원본을 가로 **240 / 960 / 1600** 으로 줄인 WebP 를 미리 만들어 둡니다. 본문은 960·1600 을
`srcset` 으로 내보내고, 게시판 목록 썸네일은 240 을 씁니다.

- 폭 기준으로만 줄이고 세로는 비율을 따라갑니다.
- **원본보다 키우지 않습니다.** 공칭 폭은 원본이 그보다 넓을 때만 만듭니다.
- 줄인 뒤 세로가 WebP 한계(16,383px)를 넘으면 그 변환본만 **JPEG** 로 만듭니다.
- GIF 는 대상이 아닙니다(애니메이션 프레임이 깨집니다).
- **요청 시점에 만들지 않습니다.** artisan 명령과 스케줄러만 만들고, 공개 경로는 이미
  만들어진 파일만 내보냅니다.

960 과 1600 이라는 숫자는 기본 템플릿의 실제 본문 폭에서 나왔습니다 — 데스크톱 848 CSS px,
모바일은 뷰포트에서 80px 을 뺀 값입니다. 960 이 데스크톱 1배율과 모바일 고밀도를,
1600 이 데스크톱 2배율을 덮습니다.

240 은 게시판 목록의 정사각 썸네일 크기(80×80 CSS px)에서 나왔습니다 — 3배율까지 덮습니다.
**이 폭은 본문에 쓰이지 않습니다.**

### 2. 제자리 변환 (PNG·JPEG → WebP)

원본 파일 자체를 WebP 로 다시 인코딩합니다. 치수는 바꾸지 않고 포맷만 바꿉니다.

**이미지 해시를 그대로 두므로 글·댓글 본문은 한 글자도 바뀌지 않습니다.** 대신 데이터베이스
행의 `mime_type`·`file_size`·`file_path`·`original_name` 을 함께 갱신합니다 — 이미지를
내보내는 쪽이 MIME 을 파일이 아니라 행에서 읽고, 다운로드 파일명도 행에서 가져오기
때문입니다.

- artisan 으로만 실행됩니다. 업로드를 가로채지 않고 자동으로 돌지도 않습니다.
- **기본이 모의 실행**이고, 실제로 바꾸려면 `--apply` 를 붙여야 합니다.
- 바꾸기 전에 원본 파일과 행 스냅샷을 배치 폴더에 백업합니다. 되돌리기 명령이 함께 있습니다.
- 결과가 원본보다 크거나 같으면 건너뜁니다.
- 가로나 세로가 16,383px 을 넘으면 WebP 로 담을 수 없어 건너뜁니다.

### 3. 응답 가공

글 상세 API 와 댓글 목록 API 의 응답에서 **에디터 업로드 이미지 img 태그만** 다시 씁니다.

- 변환본이 있으면 `src`(960), `srcset`, `sizes`, `width`, `height` 를 넣습니다.
- 첫 이미지에는 `fetchpriority="high"` 를 주고 지연 로딩을 걸지 않습니다. 나머지는
  `loading="lazy"` 입니다. 모두 `decoding="async"` 입니다.
- 링크 안에 있지 않은 이미지는 원본으로 가는 링크로 감쌉니다(새 창). 이미 링크 안이면
  감싸지 않습니다.
- 변환본이 없어도 지연 로딩·`decoding`·링크는 적용합니다.
- **대상이 아닌 img 와 나머지 HTML 은 바이트 하나 바뀌지 않습니다.**

### 4. 목록 썸네일 주소 교체

게시판 목록 API 응답의 `thumbnail` 값을 **240 변환본 주소로 바꿉니다.**

- 값이 **에디터 업로드 이미지 주소와 정확히 일치**하고, 그 해시의 240 변환본이 준비돼
  있을 때만 바꿉니다.
- 외부 주소·첨부 미리보기 주소·`null`·빈 값은 그대로 둡니다.
- 240 변환본이 없으면(원본이 240 이하 등) **원본 주소가 그대로 남습니다.**
- `thumbnail` 말고 다른 필드는 건드리지 않습니다.
- 비밀글처럼 코어가 주소를 내보내지 않은 글은 애초에 대상이 아닙니다 — 이 플러그인이
  권한을 다시 판정하지 않습니다.
- 응답 하나당 조회 1회입니다.

목록 화면은 이 썸네일을 80×80 으로 그리므로, 원본을 그대로 보내던 것과 견주면 전송량이
크게 줄어듭니다.

### 5. 다른 확장용 공개 계약 (0.3.0)

다른 확장(예: [g7-home-widgets](https://github.com/William1607cho/g7-home-widgets) 갤러리·웹진 위젯)이
에디터 이미지 주소로 변환본을 찾을 수 있게 **공개 계약**
`Plugins\Glitter\Ckeditor5Image\PublicApi\ThumbnailVariants::lookup(array $urls)`(`VERSION = 1`)을 둡니다.
다른 확장은 이 플러그인의 내부 클래스나 표를 직접 읽지 말고 이것만 씁니다.

- **입력**: 이미지 주소 문자열 목록(최대 200개). 대상은 위 4번과 같은 규칙 — 에디터 이미지 주소와 정확히 일치하는 것.
- **출력**: 주소마다 `available`(준비된 변환본이 있는가), `variants`(공칭 폭 240·960·1600 중 있는 것 →
  `url`·`width`·`height`), `source`(변환본이 있을 때 원본 `width`·`height`·`mime`).
- 변환본이 없거나(스케줄러가 아직 만들지 않음), 대상이 아닌 주소거나, "본문 이미지 가공 사용"이 꺼져 있으면
  `available = false` 이고 **원본 주소를 대신 넣지 않습니다** — 원본을 쓸지는 호출하는 쪽이 정합니다.
- 항목 수와 무관하게 조회 1회입니다. 권한은 판정하지 않습니다(비밀글 이미지 주소는 호출하는 쪽이 넘기지 않습니다).
- 쓰는 쪽의 유무 판정: 코어가 이 플러그인을 활성으로 보고 **그리고** `class_exists(ThumbnailVariants::class)
  && ThumbnailVariants::VERSION >= 1`.
- 입출력을 바꿔야 하면 `VERSION` 을 올리고 CHANGELOG 에 적습니다.

게시판 목록 응답(4번)과 글 본문 응답(3번)의 동작은 이 계약과 무관하게 0.2.0 과 같습니다.

## 설치

```
php artisan plugin:install glitter-ckeditor5_image
php artisan plugin:activate glitter-ckeditor5_image
```

## 명령

| 명령 | 설명 |
|---|---|
| `glitter-ckeditor5_image:build-variants [--dry-run] [--limit=20]` | 미생성 변환본 생성 |
| `glitter-ckeditor5_image:build-variants --backfill-width=240 [--dry-run] [--limit=N]` | 기존 원본에 빠진 폭 채우기 (아래 참고) |
| `glitter-ckeditor5_image:convert-originals [--apply] [--limit=50]` | 원본 제자리 변환 (기본은 모의 실행) |
| `glitter-ckeditor5_image:revert-originals [--batch=<id>] [--dry-run]` | 제자리 변환 되돌리기 (배치 생략 시 목록) |
| `glitter-ckeditor5_image:prune-variants [--dry-run]` | 원본이 삭제된 변환본 정리 |

스케줄러가 10분마다 변환본을 20건씩 만들고, 하루 한 번 정리합니다.

### 기존 원본에 폭 채우기 (`--backfill-width`)

**이미 운영 중인 사이트에서 0.2.0 으로 올렸다면 한 번 실행해야 합니다.**

일반 배치는 원본 단위로 "볼 일이 남았는가" 를 판정합니다. 960 변환본을 이미 만들어 둔
원본은 다시 후보에 오르지 않으므로, 폭 목록에 240 이 더해져도 **기존 이미지는 한 장도
만들어지지 않습니다.** 이 옵션은 "그 폭이 없는 원본" 이라는 다른 질문으로 대상을 뽑습니다.

```
php artisan glitter-ckeditor5_image:build-variants --backfill-width=240 --dry-run --limit=1000
php artisan glitter-ckeditor5_image:build-variants --backfill-width=240 --limit=1000
```

- 모의 실행이 대상 건수를 알려 줍니다. 먼저 돌려 확인하세요.
- `--limit` 만큼만 처리하고 남은 건수를 알려 줍니다. 나눠 돌려도 됩니다.
- **기존 변환본·표식 행과 파일은 수정하지도 삭제하지도 않습니다.** 새 행과 새 파일만 늘어납니다.
- 원본 가로가 그 폭 이하면 대상이 아닙니다(키우지 않습니다). 그런 이미지의 목록 썸네일은
  원본 주소를 그대로 씁니다.
- 처리할 수 없는 원본(픽셀 상한 초과·GIF)은 대상에서 빠집니다.

새로 올라오는 이미지는 이 명령과 무관하게 일반 배치가 세 폭을 한 번에 만듭니다.

## 설정

| 설정 | 기본 | 설명 |
|---|---|---|
| 본문 이미지 가공 사용 | 켬 | 끄면 응답을 가공하지 않습니다 |
| 중간 크기 변환본 생성·정리 | 켬 | 끄면 스케줄 작업만 멈춥니다(이미 만든 변환본은 계속 제공) |
| 이미지를 원본 링크로 감싸기 | 켬 | |

변환 품질은 따로 두지 않고 **코어의 이미지 품질 설정**(환경설정 > 업로드)을 따릅니다.

## 되돌리기

플러그인을 비활성화하면 응답 미들웨어가 등록에서 빠져 **응답이 설치 전과 같아집니다.**
본문 데이터베이스도 이미지 해시도 건드리지 않았기 때문입니다. 목록 `thumbnail` 도 원본
주소로 돌아옵니다 — 응답을 내보낼 때만 바꾸고 저장된 값은 손대지 않습니다.

제자리 변환만은 파일을 실제로 바꾸므로, 되돌리려면 배치 id 로 되돌리기 명령을 실행하세요.

```
php artisan glitter-ckeditor5_image:revert-originals            # 배치 목록
php artisan glitter-ckeditor5_image:revert-originals --batch=<id>
```

플러그인을 제거하면 이 플러그인의 변환본은 정리되지만, 현재 구현은 제자리 변환의 백업 폴더를
제거하지 않습니다. **업로드 원본 파일은 공유 CKEditor 저장소의 데이터입니다.** 제자리 변환을
한 상태라면 제거 전에 되돌리고, 백업 폴더는 복구 필요성이 끝난 뒤 별도로 검토하세요.

## 알아 둘 것

### `fetchpriority` 는 방문자 화면에서 지금은 무효입니다

기본 템플릿이 본문을 그릴 때 쓰는 DOMPurify 설정의 허용 속성 목록에 `fetchpriority` 가
없어, 방문자 화면에서는 이 속성이 제거됩니다. 봇·SSR 화면에서는 그대로 남습니다.
속성은 표준대로 내보내고 있으므로, 템플릿 쪽에서 허용 목록에 이 속성을 더하면 그때부터
방문자 화면에도 적용됩니다.

### 안전 한도

모든 이미지 작업에 imagick 자원 한도(메모리·메모리맵·디스크·면적·가로·세로·시간)를 걸고,
디코드하기 전에 원본 픽셀 수 상한을 먼저 확인합니다. 1건당 벽시계 시간도 따로 잽니다.
공개 경로에는 분당 호출 상한이 걸려 있고, 해시 형식과 허용 폭이 라우트 단계에서 좁혀집니다.

### 왜 imagick 인가

이 환경의 GD 는 번들 빌드라 WebP 인코더가 없습니다. 코어의 이미지 리사이저가 GD 로 고정돼
있어 재사용할 수 없는 것도 같은 이유입니다. imagick 은 파일을 디코드하지 않고 치수만 읽을
수 있어(`pingImage`) 압축 폭탄 방어도 값싸게 할 수 있습니다.


## 독립 플러그인 및 URL 호환성

- Plugin ID: `glitter-ckeditor5_image`
- Vendor / Author: Glitter.kr
- Repository: https://github.com/glitter-node/glitter-ckeditor5_image (예정 주소)
- 이 플러그인은 `g7-image-delivery`의 MIT 라이선스 구현을 기반으로 독립 식별자와 자원 경로를 적용했습니다. 원본 저작권과 MIT 고지는 [LICENSE](LICENSE)에 보존했습니다. Glitter.kr의 수정분 및 독립 구현 권리는 Glitter.kr에 있습니다.
- `sirsoft-ckeditor5`가 업로드 파일과 업로드 모델을 소유하므로 해당 플러그인이 필수 의존성입니다. 업로드 파일 자체는 공유 원본 데이터이며 이 플러그인은 일괄 복제·이동·삭제하지 않습니다.
- 기존 글·댓글에 저장된 `/api/plugins/sirsoft-ckeditor5/images/{hash}` 주소를 그대로 처리합니다. 콘텐츠 저장 데이터를 일괄 변경하지 않습니다.
- 새 변환본은 `/api/plugins/glitter-ckeditor5_image/variants/...` 경로로 제공합니다. 과거 `g7-image-delivery` 변환본 URL은 원본 플러그인의 라우트이므로 원본 플러그인이 비활성화되면 제공되지 않습니다. 본문 저장 주소는 원본 CKEditor 업로드 URL이므로 변환본 경로 변경의 영향을 받지 않습니다.
- 두 플러그인이 동시에 활성화되어도 각자의 변환본과 저장소를 사용합니다. 본문 응답은 원본 업로드 URL을 대상으로 하며, 이미 변환된 `<img src>` 와 기존 링크는 다시 감싸지 않도록 동작합니다.
